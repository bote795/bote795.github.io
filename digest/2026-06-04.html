Builder's Briefing Thursday, June 4, 2026

Cognition scrapped its Windsurf brand and rebuilt Devin as a multi-agent hub the first serious UI design for "supervise N agents at once." And a researcher spent $1,500 letting frontier LLMs attack a deliberately-vulnerable app and published what they found the empirical security data point builders have been missing.

The IDE Is Becoming an Agent Hub

Cognition Devin Desktop + Agent Client Protocol (ACP)

Cognition retired the Windsurf brand and relaunched as Devin Desktop a Kanban board of every agent you're running (in-progress / blocked / ready for review), regardless of vendor. OpenAI agents, Anthropic agents, and others all land in the same interface. The accompanying Agent Client Protocol (ACP) is now backed by JetBrains, Google, GitHub, and 25+ agents, which means switching between providers stops requiring a new IDE. Devin Local, the on-device component, is a Rust rewrite of Cascade roughly 30% more token-efficient. The bottleneck in AI coding has changed from writing code to supervising parallel agents; Devin Desktop is the first product designed around that reality.

Tune a Small Model, Beat a Frontier One

Microsoft MAI Full Lineup + Frontier Tuning

Microsoft shipped all seven MAI models MAI-Thinking-1, MAI-Code-1-Flash, MAI-Image-2.5, MAI-Image-2.5 Flash, MAI-Transcribe-1.5, MAI-Voice-2, and MAI-Voice-2-Flash all trained from scratch on commercially-licensed data with no distillation. The headline is Frontier Tuning: enterprises run RL on proprietary workflows, weights stay on-premises, and a Microsoft-demo Excel-tuned variant matched GPT-5.4 at roughly 10x lower cost. For any workflow with a measurable task (document parsing, transcription, SQL generation), fine-tuning a small model on your own data is now a concrete cost lever, not a research project. The full multimodal set (image, voice, transcription) also makes this a practical exit from managing three separate API vendors.

Short Takes

PostHog Karpathy Autoresearch found a 3-year-old ClickHouse bug overnight Setup: per-candidate sandboxes running pi-autoresearch, each iterating, committing, benchmarking, and journaling against a budget while the team slept. Result: 62% reduction in granule scans, 11% perf improvement, bug that had sat for three years. Directly reproducible for any app with a measurable benchmark. One hard caveat: always gate merges on an independent benchmark the autoresearch loop has known Goodhart failure modes and can game its own reported score. (PostHog — see Worth Your Time below.)

Key Learnings for Builders

New metric: $/Mt (dollars earned per million tokens). Track revenue per million tokens spent $2,000/mo on 10M tokens = $200/Mt. If your number is low, you're burning tokens without converting them to output. This is a fast gut-check on whether AI spend is working.

Token consumption is not a productivity metric. One team ranked members by token burn; adoption jumped from 32% to 84% and the bill exploded. Spec-driven prompts (define "done" before you prompt), task-attached runs, and humans in the loop keep bills flat and work shipping. Structure drives behavior before scale does.

The flat-fee era for agentic features is ending. GitHub moved agentic features to metered billing June 1. Anthropic follows June 15. If you're quoting customers a flat AI price, reprice now or build a token budget into every contract.

Route by failure mode, not benchmark rank. Opus 4.8 wins on dirty data and source-grounded synthesis. GPT-5.5 wins on visual and frontend work. On long-running Opus 4.8 tasks, "high" effort outperforms "max" max burns tokens, triggers compactions, and loses state continuity. Pick by what can break the specific job, not by average leaderboard position.

Metered AI billing rewards intentional use. Real productivity from AI is task-bounded: high token counts often signal a missing endpoint definition, not high output. Define "done" before every run, keep humans in review loops, and watch tokens-per-task trend down as your prompting matures.

Agent-native SaaS is a real product gap. Buying flow is inverting: agents read pricing pages, compare competitors, check for MCP and API layers, and transact without a human visiting a site. Every category of SaaS has an agent-native version waiting to be built communication, payments, memory, analytics.

Headcount cuts for AI don't pencil out. A majority of companies that cut staff for AI regret it. Roughly a third to half of those roles got rehired within months, often at higher cost than the savings. AI handles routine tasks that never needed a person. The judgment calls still do.

"Token thief" employees are a hiring signal, not just a cost leak. Employees using company API tokens for personal projects are likely the people who understand agents best. Treat it as a retention signal before a cost-control problem.

The Rise of the Full-Stack Builder and Hyper-Leveraged Generalist with Microsoft CEO Satya Nadella (@NoPriorsPodcast)

Watch

Satya Nadella reframes the AI era as an ecosystem play where the prize is letting every company "operate at the frontier with their own frontier intelligence." His central, repeated thesis: a company's most defensible IP is no longer tenure or headcount but its private eval — and the acid test of being in control is whether you can swap model A for model B against that eval and still hill-climb. He argues for open, multi-model "harnesses" (models + data + tools in a loop), predicts SaaS gets unbundled and rebundled, and champions the hyper-leveraged generalist / full-stack builder as the role with the most upside.

Key takeaways:

  • Platform value lives ABOVE the platform — a real platform creates more value for others than it captures itself. Microsoft's "third act" is being the harness/eval/frontier-intelligence enabler (after OS → cloud).
  • Private eval is the new IP. Public benchmarks can all be "maxed" and are no longer critical; the durable moat is a company's private eval plus the traces it collects. Mindset shift: Before: IP = length of human experience / tenure → After: IP = the eval and the experience of applying agents to your company.
  • The model-portability acid test — "You have a private eval, you're on model A. Can you switch to model B and still climb up? If you can, you're in control. If you can't, you're not." This is the single most actionable test in the interview.
  • Build with an open, multi-model harness — the harness defines models + data + tools in a loop. Don't lock yourself to one model. Existence proof: Microsoft's M-dash multi-model security harness found vulnerabilities a single-model approach missed.
  • Context prep is where the magic is — the hardest lesson of the last two years is how much work it takes to prep the context layer so a plan executes efficiently. Use progressive disclosure of tools to stay token-efficient.

The Only Claude Skills Tutorial You Need (Add Evals and Memory) (@PeterYangYT)

Watch

Peter Yang builds an AI "skill" from scratch in Claude Code — an edit-post skill for editing long-form newsletter copy — and walks through five steps to make skills that improve themselves. The high-value ideas: separate the skill instructions from personal context/examples, write an explicit trigger description, build a pass/fail evals.md run by a separate agent in a loop until the output passes, and add a memory.md for lessons that can't be captured as pass/fail checks. Closing point: skills only get you 80-90% there; the last 10-20% is human review and taste.

Key takeaways:

  • A skill is just a folder of instructions AI triggers for a task — the value is encoding your personal knowledge and taste into something reusable.
  • Separate skill.md from personal context/examples — three reasons: (a) AI doesn't reload all your examples every run, it loads only the relevant context based on the input; (b) you can share the skill without leaking personal/confidential material; (c) cleaner, shorter skill file.
  • Give at least a couple of different examples, never one — a single example causes the skill to overfit and produce output you don't actually want.
  • The description is the trigger, not the skill body — AI only reads the skill's name + description to decide whether to invoke it. Write "use when [X]" explicitly or the skill won't fire reliably.
  • Pass/fail evals beat score evals — AI can't meaningfully tell a 3 vs 4 vs 5 out of 5 (it makes it up). Up to 10 binary pass/fail checks across categories (intro, voice, substance, CTA) are far more useful.
